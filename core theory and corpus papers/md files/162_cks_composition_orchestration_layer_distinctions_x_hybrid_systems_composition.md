## Attribution

This work derives from and formalizes the Coordination Knowledge Substrate (CKS) pattern introduced in *Coordination Outside the Model: A Human-Governed Substrate Pattern for AI Systems* (Li, April 2026). It does not introduce new axioms. Its sole contribution is to articulate, in operational form, the emergent architectural property produced when two foundational CKS commitments — the orchestration-layer distinctions developed in the source paper's §4.3–§4.4 and the hybrid-systems composition pattern set developed across §2.3, §6.1, §6.2, and §11.3 — are jointly instantiated in a single deployment. The note is the twenty-sixth in the Phase A4 composition-pair series and closes the cluster that operationalizes the orchestration layer (A4.23–A4.26).

## Abstract

The CKS pattern commits to two architectural propositions that, taken alone, leave a question unanswered between them. The orchestration-layer distinction commits that the coordination-knowledge layer where the substrate sits is distinct from the coordination-mechanism layer where workflow engines and agent frameworks sit, and from the control-plane layer where Stevens-style operational primitives sit, with none substituting for the others. The hybrid-systems composition pattern set commits that an adjacent AI component sits in Pattern A (input to a cell), Pattern B (derived view of substrate content), or Pattern C (separate concern), and that a hybrid deployment is CKS-coherent if and only if every adjacent component sits in one of those three positions. The question neither answers alone is where the orchestration layer itself sits relative to the three patterns when both commitments are simultaneously instantiated. This note formalizes the answer as *orchestration composition coherence* — the architectural pattern under which orchestration triggers cells, cells consult adjacencies through Pattern A, orchestration may produce Pattern B derived views, orchestration is itself a Pattern C separate concern relative to substrate authority, and the cell-rule chain is preserved across all three patterns. The note specifies the four operational components, identifies what the composition forces beyond either commitment alone, names four anti-patterns specific to the composition, and provides an operational test with three sharpening properties. The note closes the A1.15 composition cluster.

## 1. Why the composition pair needs to be formalized as standalone

The orchestration-layer distinction and the hybrid-systems composition pattern set are commitments at different architectural axes — layer and position — and each is sufficient for the question it answers in isolation. Neither answers the question that arises when both are simultaneously instantiated.

A workflow engine that triggers a cell, and a cell that consults a retrieval-augmented generation index in the same execution, are simultaneous instances of the layer distinction (the engine sits at the coordination-mechanism layer per §4.3) and the composition pattern set (the index sits in Pattern A relative to the substrate). The layer-distinction commitment alone does not classify the engine relative to the three composition patterns. The composition-pattern set alone does not say whether the engine itself is an "adjacent AI component" within its scope or something outside it. The composition is what specifies the answer, and naming it as a property of the architecture is what allows downstream deployments to instantiate both commitments without drifting into a position the architecture does not name.

The emergent architectural property is *orchestration composition coherence*: the property under which the orchestration-layer distinctions integrate with the three composition patterns without orchestration becoming a substrate substitute, without composition patterns being instantiated from the orchestration layer rather than from cells, and without any of the three patterns moving authority away from the cell-rule chain. The property is operationally distinct from each commitment in isolation. The orchestration-layer distinction alone specifies orchestration's architectural layer but not its composition-pattern position. The composition-pattern set alone specifies adjacent components' composition positions but does not classify the orchestration layer. The composition specifies the integration.

This note also closes the A1.15 composition cluster. The cluster's four pairings — orchestration-mediator separation (A4.23), orchestration retraceability (A4.24), orchestration source-of-truth distinction (A4.25), and orchestration composition coherence (this note) — collectively specify the orchestration layer's relations to the four foundational commitments most directly entangled with it. With the cluster closed, Phase A4 progresses to its fifth tier, in which the three composition patterns are themselves operationalized as standalone properties (A4.27–A4.30 closing Phase A4).

The load-bearing source-paper sections are §4.1–§4.4 (the governance boundary, the AI-as-substrate-mediator commitment, the four-layer landscape, and the differentiation from MACI and control-plane work), §6.1–§6.2 (the linear-cost composition framing), and §11.3 (substrate as source of truth in the deployed instantiation). The note does not extend the source paper's commitments; it formalizes what their composition entails.

## 2. The emergent architectural property as four operational components

Orchestration composition coherence is operationally specified by four properties that must hold simultaneously in any deployment where both commitments are instantiated.

*(i) Orchestration triggers cells; cells consult adjacencies through Pattern A.* When a workflow engine, scheduling system, or agent framework determines that a cell should execute, the trigger crosses into the coordination-knowledge layer through the cell's invocation. The cell then operates under its orchestration rule and may consult adjacent AI components — RAG indexes, fine-tuned models, vector databases, external knowledge stores — as Pattern A inputs. The Pattern A consultation originates from the cell, not from the orchestration layer. An engine that consults an adjacency directly and feeds the result to the cell as a parameter has not instantiated Pattern A as the architecture defines it; the cell's rule has been displaced from the consultation it is supposed to govern, and the substrate write that follows carries no provenance for the consultation it depended on.

*(ii) Orchestration may produce Pattern B derived views.* A workflow engine, scheduling system, or agent framework may maintain projections of substrate content for its own purposes — execution-time displays, branching predicates, retry conditions, scheduling decisions. These projections sit at Pattern B relative to the substrate: they are derived views, regeneratable from substrate state, non-authoritative on coordination questions, and resolved in the substrate's favor when they disagree. Orchestration that maintains such a view does not gain authority over the substrate by virtue of holding the projection; the projection is a Pattern B object the architecture already supports, and its presence in the orchestration layer does not change its position.

*(iii) Orchestration is itself a Pattern C separate concern relative to substrate authority.* The orchestration layer's own state — execution logs, step transitions, retries, parallel branches, scheduling decisions, agent-framework memory — is execution state, not coordination state. It is persisted at the coordination-mechanism layer, governed by the orchestration object's lifecycle, and discarded or archived at that layer. Relative to the substrate's source-of-truth scope, orchestration occupies the architectural position Pattern C names: a distinct concern that does not affect coordination state, coexisting with the substrate without architectural coupling at the authority level. The orchestration layer is not an "adjacent AI component" in the primary composition-pattern sense — it is at a different architectural layer entirely — but the Pattern C relation is the appropriate analogue for how the two layers' authorities relate.

*(iv) The three composition patterns preserve the orchestration–cell–rule architecture.* Whichever of the three patterns a deployment instantiates for any given adjacent AI component, the chain orchestration → cell → rule → substrate write is preserved. Pattern A locates adjacent components inside the cell's reasoning environment, not above it. Pattern B locates derived views outside the substrate's authoritative scope, not in front of it. Pattern C locates separate concerns outside the coordination layer entirely. None of the three patterns moves a write authorization away from the cell's rule into the orchestration layer or into an adjacent component. Composition coherence is the property that this preservation holds across whichever pattern a given adjacent component occupies.

The four properties are jointly sufficient. A deployment that satisfies (i)–(iv) is composition-coherent on the orchestration axis; a deployment that fails any of them has drifted into one of the anti-patterns enumerated in §4.

## 3. What the composition forces beyond either commitment alone

The orchestration-layer distinction alone forces the layer separation. The hybrid-composition pattern set alone forces the three-pattern positioning of adjacent AI components. Neither alone forces a position for the orchestration layer relative to the three patterns.

The composition forces three operational propositions that neither commitment yields independently. *First*, orchestration is not an adjacent AI component in the primary composition-pattern sense; it is at a different architectural layer, and the appropriate analogue for its relation to the substrate is the Pattern C separate-concern position rather than the Pattern A or Pattern B positions. *Second*, Pattern A consultations originate from cells, not from the orchestration layer; the cell's rule authorizes the consultation and records its provenance, and an engine that consults adjacencies on the cell's behalf has displaced the rule from the consultation it governs and broken the retraceable path the substrate carries. *Third*, bidirectional coupling between orchestration and substrate must pass through cells under rules — updates from substrate to orchestration are Pattern B view rebuilds, and updates from orchestration to substrate are Pattern A consultations producing cell writes under rules. There is no admissible direct link between the orchestration layer and substrate content; the cell-rule chain is the only authorized mediator.

These propositions are operational consequences of the composition. None is added beyond the two foundational commitments; each is what those two commitments jointly entail.

## 4. Anti-patterns specifically violating the composition

The composition produces specific anti-pattern instantiations, each a specialization in the orchestration context of an anti-pattern already named in the composition-anti-pattern sibling material.

*Orchestration-as-substrate-substitute.* The deployment treats workflow execution state, scheduling decisions, or agent-framework memory as if it were coordination state. Participants answer "what was decided and why" by reading workflow logs rather than substrate content; the substrate's coordination scope narrows over time, and the orchestration layer accretes the role the composition pattern set reserves for the substrate. The drift is the migration of source of truth that §6.2 names as context rot, instantiated in the orchestration layer rather than in a derived view.

*Orchestration-direct-substrate-write.* The orchestration layer writes substrate content directly, bypassing the cell-rule chain. This typically appears as a workflow engine that updates substrate fields when steps complete, or as an agent framework whose terminating agents write to the substrate without a cell mediating. The write appears in the substrate without orchestration-rule trace and without the authority constraint a cell would have applied. This is the orchestration-context instantiation of the ungoverned-writer anti-pattern and a violation of AI-as-substrate-mediator.

*Orchestration-bidirectional-coupling.* The substrate and the orchestration layer update each other through automated processes that no human-authored orchestration rule governs — for example, an engine that re-derives execution state from substrate content while also injecting derived state back as substrate fields. The cell-rule mediator is bypassed; path retraceability breaks; and the layer distinction is silently relaxed. The repair is to route each direction through the cell-rule chain — Pattern A for orchestration → substrate (the engine triggers the cell, which performs the consultation under its rule and writes substrate with provenance), and Pattern B view rebuild for substrate → orchestration (the engine refreshes its derived view from authoritative substrate state).

*Pattern-A-from-orchestration-not-cells.* The orchestration layer consults an adjacent AI component directly and feeds the result into a cell as a parameter or context object, rather than triggering the cell to perform the consultation under its rule. Pattern A's three properties — provenance crosses cleanly, the substrate is authoritative on coordination questions, the cell's outputs remain rule-governed — do not transfer to a consultation issued from the orchestration layer; the consultation has been separated from the rule that governs it, and the substrate write that follows carries no provenance for the consultation it depended on. The fix is to issue the consultation from inside the cell's execution and to record the adjacent component's involvement as substrate provenance, which is what the Pattern A position actually requires.

A more general failure mode is the deployment of an "AI-orchestrator" object that combines workflow-engine, agent-framework, and substrate roles into a single layer in the name of integration convenience. Each of the four specific anti-patterns instantiates inside this object because the layers it conflates are exactly the layers the orchestration-layer distinction separates. The architectural correction is to decompose the object into its constituent layers and apply the per-anti-pattern repair to each.

## 5. Operational decisions the composition forces

A composition-coherent deployment makes four architectural decisions explicit. *First*, the orchestration layer's relation to the substrate is documented as Pattern C separate concern: orchestration handles execution state at the coordination-mechanism layer, and the substrate handles coordination state at the coordination-knowledge layer, with the two layers' authorities separate. *Second*, cell triggering from orchestration and Pattern A consultations from cells are documented as distinct events; the trigger is a coordination-mechanism event recorded at that layer, and the consultation is a Pattern A event recorded as substrate provenance. *Third*, Pattern B derived views maintained by orchestration are specified as such, identified as non-authoritative, and tied to a regeneration procedure from substrate state. *Fourth*, the four composition anti-patterns are excluded from orchestration architecture by named architectural decisions reviewable as part of the deployment's posture, not deferred to runtime convention.

These decisions are not procedural promises; they are properties of the deployment's architecture that participants can verify by inspecting where state is held, what writes the substrate, and what the cell-rule chain authorizes.

## 6. What the composition is not

Three readings the composition is not.

*Not the orchestration-layer distinction alone.* The orchestration-layer distinction specifies the layer separation; it does not classify orchestration's position relative to the three composition patterns. A deployment that maintains the layer distinction but misclassifies orchestration as a Pattern A "adjacent component" — for example, by treating the workflow engine as a black-box adjacency that the substrate consults via Pattern A — violates the layer distinction itself and is not composition-coherent.

*Not the hybrid-composition pattern set alone.* The composition-pattern set specifies the three positions; it does not say whether orchestration falls inside its scope. A deployment that classifies adjacent AI components into Pattern A/B/C but leaves the orchestration layer unclassified, or treats it as out of architectural concern, is not composition-coherent because the orchestration layer's relation to the substrate is unspecified.

*Not "orchestration-as-coordination-state".* Some deployments adopt the framing that the orchestration layer's execution state is coordination state, on the grounds that "what ran" is part of "what was decided." The framing collapses the two layers' commitments and produces the orchestration-as-substrate-substitute anti-pattern. Execution state and coordination state are different categories with different scopes (per §11.3); orchestration composition coherence is the property under which they remain distinct.

## 7. Why the composition pair is load-bearing

Naming orchestration composition coherence does what no individual commitment does. It closes the A1.15 composition cluster: with orchestration-mediator separation, orchestration retraceability, orchestration source-of-truth distinction, and orchestration composition coherence, the four most architecturally entangled relations between the orchestration-layer distinction and the rest of the foundational commitments are operationally specified, and closure of the set is itself part of the prior-art posture this series defends. It provides a cross-cluster overlap point with the hybrid-composition pattern set, completing the composition-pattern side of its own cluster's foundational pairings. It supports the human-selective composition coherence pair (A4.18) by specifying where orchestration sits when human-selective composition is exercised: human-selective composition determines which adjacent components occupy which patterns; orchestration composition coherence determines where the orchestration layer sits relative to those choices, and the two properties are jointly required for a complete composition account. And it distinguishes CKS from architectures in which orchestration is the substrate substitute — the single-object pattern that combines workflow engine, agent framework, and coordination state into one layer being the dominant alternative in 2024–2026 multi-agent system designs.

## 8. Operational test

A deployment instantiates orchestration composition coherence if and only if the following three sharpening properties hold simultaneously, at all times during the deployment's existence, in addition to underlying compliance with the orchestration-layer distinction and the hybrid-composition pattern set.

*(e.1) Orchestration-Pattern-C-from-substrate.* Orchestration's own state — execution logs, agent-framework memory, scheduling decisions, retry counters, branching state — is treated as a Pattern C separate concern relative to the substrate. The substrate, not the orchestration layer, is authoritative for coordination questions; the orchestration layer's state is authoritative for execution questions, and the two scopes do not overlap. A reader who asks "what was decided, by whom, under what authority, with what rationale" reaches the substrate; a reader who asks "what step ran, in what order, with what retries" reaches the orchestration layer.

*(e.2) Pattern-A-from-cells-not-orchestration.* Consultations of adjacent AI components originate from cells under their orchestration rules. Orchestration objects do not consult adjacencies on cells' behalf, and substrate provenance for cell writes records the adjacent components the cell consulted. A reader who inspects the substrate provenance for any cell write can identify which adjacent components were consulted in producing it; a reader who finds an adjacency consultation in the orchestration-layer logs but no corresponding consultation in substrate provenance has identified a Pattern-A-from-orchestration-not-cells violation.

*(e.3) Composition-cluster closure.* The four-note A1.15 composition cluster — orchestration-mediator separation, orchestration retraceability, orchestration source-of-truth distinction, and orchestration composition coherence — is jointly satisfied. Closure of the cluster, not the satisfaction of any individual sibling, is what the test verifies: the orchestration layer is separated from the mediator role, retraceability crosses the orchestration boundary cleanly, the orchestration layer is distinct from the source-of-truth role, and orchestration composition coherence holds.

A deployment that fails any of (e.1), (e.2), or (e.3) may run a useful coordination workflow, and may instantiate other valuable properties, but it is not orchestration-composition-coherent in the sense the composition pair specifies.

The one-sentence form of the test: a deployment is composition-coherent on the orchestration axis if and only if orchestration triggers cells, cells consult adjacencies, the substrate is the source of truth for coordination, and the orchestration layer's state is execution state — never coordination state.

## 9. Why naming this composition pair as standalone matters

The orchestration-layer distinction and the hybrid-composition pattern set are commitments at different architectural axes, and a deployment that satisfies each in isolation may still drift into an anti-pattern at their intersection. The drift is mechanical: when both commitments are instantiated, the question "where does orchestration sit relative to the three patterns?" has an answer not visible from either commitment alone.

A team facing the question "should the workflow engine consult the RAG index directly, to save a hop into the cell?" needs a frame that surfaces the commitment the shortcut would violate. "Pattern A consultations originate from cells, not from orchestration; the cell records the consultation's provenance" is that frame, and the proposed shortcut is identifiable as a Pattern-A-from-orchestration-not-cells violation. A team facing the question "should the engine maintain its own copy of substrate state to make scheduling decisions?" needs a frame that distinguishes a Pattern B derived view (admissible) from a substrate substitute (not). Without these frames, the same decisions read as sensible engineering simplifications and are taken without recognizing what they cost.

Naming the pair as standalone also closes the A1.15 composition cluster. With the four-note set in the public record, the orchestration-layer side of the architecture is operationally specified across the four commitments most directly entangled with it. Subsequent Phase A4 work moves to the fifth tier — operationalizations of the three composition patterns themselves as standalone properties — which closes Phase A4.
